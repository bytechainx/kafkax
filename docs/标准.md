# kafkax 标准

**crate**：`kafkax` v0.1.0 · 依赖：`rskafka`、`tokio`、`bytes`、`rustls` / `webpki-roots`、`serde`、`thiserror`、`toml`、`tracing`

## 1. 定位

kafkax 提供纯 Rust 的 Apache Kafka 适配原语：连接池、等待 broker 确认的生产者、按显式
分区 + 起始 offset 的消费者、应用层 offset 位点持久化（at-least-once）与健康检查。
底层为 `rskafka`，无 librdkafka / libsasl2 系统依赖。不提供 consumer group / rebalance、
事务 / exactly-once、schema registry、自动重连或隐式重试。

## 2. 字段治理

- 环境变量前缀统一为 `FOUNDATIONX_KAFKAX_`；公开 `ENV_*` 常量，禁止调用方硬编码字符串。
- 配置来源优先级（低 → 高）：默认值 → TOML（`from_toml`）→ 环境变量（`from_env`）→ builder。
- TOML 时长字段可写 `{ secs = 30 }` / `{ secs = 1, nanos = 500000000 }`，或整数毫秒。
- `sasl_username` / `sasl_password` **禁止**出现在 TOML；凭据只能经环境变量或 builder 注入，
  `Debug` 输出脱敏。
- `sasl_mechanism` 仅接受 `PLAIN`；空串 / `none` 表示关闭；提供了凭据却未启用机制直接报错。
- `from_toml` 的错误消息**不得**回显 TOML 源码片段（出错行可能承载凭据）：只保留错误摘要、
  行号与字节区间。

## 3. 安全约定（`validate()` fail-closed）

- 远程 broker 必须启用 TLS，仅回环地址允许明文。
- broker 地址禁止内嵌 userinfo。
- `security_protocol()` 只返回 `PLAINTEXT` / `SASL_PLAINTEXT` / `SSL` / `SASL_SSL` 四种。
- TLS 使用 rustls，默认信任 `webpki-roots`；自定义 CA 须同时开启 TLS。

## 4. 失败与并发

- 不做自动重连与隐式重试；连接失败即返回错误，是否重试由调用方按
  `KafkaError::is_retryable()` 决定。
- `KafkaProducer::publish` 等待 broker 确认，受 `delivery_timeout` 与关闭信号约束。
- `KafkaConsumer` 按显式分区消费，位点由应用经 `OffsetCommitStore` 自管；
  `AtLeastOnceConsumer` 只有显式 `ack` 成功后位点才前进，未 ack 即退出会重投。
- `FileOffsetStore` 采用原子写入，避免半写状态。
- `close(timeout)` 拒绝新请求、取消在途 I/O 并等待在途操作释放。
- `KafkaMessage::payload` 为 `Option<Bytes>`：`None` 表示 tombstone，与零长载荷可区分。

## 5. 验收

```text
cargo fmt --all --check
cargo test --all-targets
cargo clippy --all-targets -- -D warnings
```

集成测试全部离线运行：不依赖真实 broker，不可达路径统一使用 `127.0.0.1:1`（必然拒绝）
与短超时。至少覆盖配置三来源与优先级、TOML 凭据拒收、SASL/TLS 组合校验、
`partition_for_key` / `encode_bus_id` / `parse_bus_id` 纯函数、错误可重试分类、
offset store 读写与原子性、公开 API 面。
